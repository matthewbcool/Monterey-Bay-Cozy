# Avatar Creator and Testing Gym

The **Avatars** tab now creates original coastal characters, and **Testing Gym** takes the current character into a small playable Lovers Point world. Open `http://127.0.0.1:5191/?tab=avatars` or `?tab=gym`. These are local browser prototypes; there is no account, multiplayer service or cloud save.

## Create, dress and save

The creator offers height and build sliders, eight skin tones, five hairstyles, three eye shapes, two expressions, optional face lines, hair/eye colors, and separate top, bottom and shoe colors. Tops include a tee, hoodie and fishing vest; bottoms include shorts, trousers and a skirt. Every combination is available without gender restrictions. A downloaded/imported recipe can retain a custom opaque hex color; the UI shows its current swatch.

**You → Height & build** offers a **1.20–1.80 m** nominal height slider in 1 cm steps and a **0.80–1.25** body-width/depth slider in 0.01 steps. Build keeps the head, face and hair proportions intact. **Reset size** returns to 1.45 m and the original build, keeping the rest of the design. Height is an artistic reference: hair may extend above it. Native range controls work with touch and keyboard arrows, Home and End. The preview keeps a common viewing distance, so the height difference remains visible. `heightMeters` is the nominal height; `bodyBuild` is the body width/depth multiplier.

Size stays with each character through outfit changes, local saves and JSON export/import. Version 1 recipes without `heightMeters` or `bodyBuild` keep their original 1.45 m / 1.00 appearance. Values outside the supported range are clamped; invalid or missing values use the defaults. Clothing and the rig are generated at the chosen metre dimensions. The public root stays unscaled, and held library equipment keeps its real-world size. Changes during a continuous slider drag are coalesced; releasing it applies the latest value immediately.

**Face → Face lines** offers **None**, **Soft**, and **Defined** for older-looking characters. Soft adds fine outer-eye and smile creases; Defined adds stronger creases plus under-eye and forehead lines. They follow the skin tone and head motion, independently of blinking. Hair can naturally cover some forehead lines. The choice persists through outfit changes, browser saves and JSON import/export. Older version 1 recipes without `faceLines` default to None, preserving their original appearance.

Appearance and clothing are separate fields in a small `AvatarDesign` recipe. Changing an outfit keeps the skin, face, hair, height and build. Geometry is regenerated only when a design changes. The renderer owns one skinned color batch; modular design fields do not mean one draw per garment. Tops and bottoms share the rig, and arbitrary external clothing meshes are not supported yet.

**Save character** creates a record in this browser's local storage; **Save changes** updates the loaded record. **Save as new** keeps an additional design, up to 24. **Saved characters & files** loads existing designs and downloads/imports a versioned JSON recipe. The gym can switch among saved characters or use the current unsaved design. Browser storage is origin-specific, so `localhost`, `127.0.0.1`, another port and a deployed site have separate collections. Download a JSON copy before clearing browser data or changing devices.

The collection and portable file formats have a version number. Reads validate format, IDs, enum choices, colors and file size; imported files contain appearance data, never executable code or model URLs. Storage failures are reported without claiming success. Unknown collection versions or corrupted collections are preserved and block writes; export of the current design remains available. Loading a different character replaces the in-memory draft, so save or download edits before loading another.

## Movement and interactions

In the gym, **WASD / arrows** walk relative to the camera, **Space** jumps (and swims up), **C** dives while swimming, **Shift** runs, **E** interacts, **Q** opens the emote wheel, **1 / 2 / 3** are quick wave, cheer and sit, and dragging/scrolling changes the camera. Pressing the active emote again, moving or jumping stands back up. Touch input shows a d-pad, a Run toggle and a large Jump button (Up and Dive while swimming); desktop players do not see them. The play HUD keeps the world clear: a compact place label, **Edit character**, and a **Menu** holding the character picker, **Back to start**, **Try swimming**, **Park overview / Walk view**, a controls reference and the world rendering notes. Escape or a tap outside closes the menu. One contextual prompt (key cap plus action, such as **E · Take a breather**) appears only beside an available station, with its description above it; it is hidden elsewhere. A short key hint fades once the player has walked and hopped around. Breath is a small ring beside the character while submerged (see below). Clicking a HUD button returns keyboard focus to the world, so Space and WASD keep playing; a keyboard-focused button keeps its own Space/Enter activation.

### Emote wheel

The three loose emote buttons became one **Emotes** button and a radial wheel, so the HUD stays small as poses are added. **Q**, the button or a controller's **Y** opens it. Choose with a click/tap, the arrow keys and Enter, or by pushing the left stick toward an item and pressing **A** (or **X/Y**); **B**, Escape, Q or a tap outside closes it. Number keys still pick directly. While the wheel is open it owns movement input, and closing it releases held buttons and waits for the stick to recentre, so the confirming press never also jumps or walks away from the pose. New emotes are one entry in `GYM_EMOTES` (`src/viewer/avatarWorkbench.ts`) once the rig has the pose.

### Controller support

Standard-mapping gamepads (Xbox, PlayStation, Switch Pro and others that browsers report as `mapping: 'standard'`) work through the Gamepad API, polled once per frame by `src/viewer/gamepad.ts` with no extra events or allocation. **Left stick** moves (analogue: a light push walks slowly), **right stick** orbits the camera, **A** jumps/swims up, **B** runs on land, dives in water and rows faster, **X** interacts, **Y** opens the emote wheel, the **d-pad** gives quick wave/cheer/sit, and **Menu/Start** opens the gym menu. While aboard the dive boat, **Y** is the secondary prompt and **B** drives faster. Sticks use an 18% radial dead zone rescaled to full range. Key caps in the hint, prompts and wheel switch to controller letters as soon as a pad is used and back on the next key or mouse press. Glyphs are letters, not a specific vendor's icons. Browser checks used a scripted standard-mapping pad; no physical controller has been tested yet.

### Jumping

A jump rises **0.55 m** for every body size, under an authored **24 m/s²** game gravity (about 0.43 s in the air). Holding Space gives the full height; a quick tap cuts the rise to a short hop. A press up to **0.14 s** before landing is buffered and fires on touchdown; holding the button never auto-repeats. Air control is reduced (45% of ground acceleration), so a hop commits to its direction. In the air the feet may pass over a ledge they have cleared, which lets a jump climb low walls and stair edges up to about 0.55 m that walking refuses (walking steps at most 0.28 m); drops keep the grounded step limit, so a jump never launches off a cliff or the sea wall. Solid collision proxies remain 2D footprints: a jump does not clear rocks, benches or props. Swimmers tread water instead of jumping; a hop over shallow water is classified as wading or swimming only on landing. Interactions and emotes wait until the character lands.

The rig tucks the knees and lifts the arms while rising, opens the arms for balance while falling and plays a 0.24 s knee-bend dip on landing, scaled by impact speed. These are pose-only bone changes: no geometry, draws, materials or textures. The contact shadow stays on the ground and tightens as the character rises. The camera follows the ground under a hop rather than the hop itself and eases toward the player; reduced motion keeps the immediate follow without easing.

Jump tuning lives in `AVATAR_JUMP` in `src/viewer/avatarController.ts`. Input is a plain `{ x, z, run, jump }` record per step; the controller detects presses itself. Identical input streams produce identical positions, and `getState()` includes `grounded` and `verticalVelocity` so a hop can be paused, saved or handed between machines mid-air. Snapshots without these fields restore grounded. The rig reads only `airborne`, `verticalVelocity` and a landing impact speed, all derivable from replicated controller state, so a remote player can animate from the same fields as the local one. Server authority, prediction and reconciliation are not implemented.

The built-in controller accelerates smoothly, normalizes diagonal movement, turns toward travel and checks a size-aware clearance circle (28 cm at the original size, up to 43.45 cm at maximum height/build) against the coastline, buildings and scene objects. Walk/run speeds are authored at **1.7 / 3.5 m/s**. Substeps prevent crossing thin obstacles during a long frame. Height and build do not change movement speed or the breath allowance. Root position and heading belong to the controller; the visual rig owns animation, which makes future physics or network placement possible without two systems fighting over transforms.

The rig has idle breathing, walking, running, jumping, landing, swimming, treading water, automatic blinks, wave, cheer, seated and casting poses. Explicit movement leaves an emote. Reduced motion removes idle sway, automatic blinks, camera damping and repeated decorative movements while keeping requested walking and poses usable. The workbench stops its animation loop when hidden or when another tab is selected.

The original exercise stations now let you inspect the tackle box, pick up the spinning rod, approach the rowboat, cast beside the dock and observe a bat star. The dive boat and Otter Man suit add further equipment interactions. Picking up the rod attaches the original library asset to the hand and removes its former collision proxy. **Return rod**, reset, or leaving the gym restores it. Casting plays one anticipation/release/recovery arc. The invented spawn bench has been removed following the location correction; the ground Sit emote remains. Boat seating uses the resized rig’s seat-contact guide. The rod and tackle box are beside the rowboat landing. Shorter characters can naturally have their feet above the ground while seated.

Inspection stations present descriptions; they do not simulate opening the tackle box. Casting currently tests pose and reach; catching fish, line physics and multiplayer authority remain future experiments. The controller uses the gym’s supplied ground-height function, with bounded steps at height changes and the kinematic jump described above. It has no full rigid-body engine. Terrain routes and boat behavior are developed in the [gym iteration](testing-gym-geography.md).

## Swimming and breath

Choose **Swim** or **Tread water** in the creator's animation menu to inspect the stroke. In the Testing Gym, **Try swimming** moves you to the accessible east beach and faces the camera toward the bay. Walk forward with **W / ↑** or the forward touch button; deep water automatically switches the controller to swimming. Move back toward dry sand to leave the water. Shallow water uses the walking pose until the depth reaches **0.85 m at the original height**, scaled by the selected height (about 0.70–1.06 m). The waterline follows the same height scale.

The authored rule gives **20 seconds underwater**, at one second of breath per simulated second. Surface swimming does not drain breath. The ring appears only while submerged and warns at **5 seconds**. Surfacing, wading, reaching land or boarding either boat immediately resets breath to **20** and hides the ring. At zero, the character returns to the last safe shore position with full breath. These are game rules, not a physiological model.

Breath shows as a **48 px ring beside the character's head**, projected each frame and clamped inside the view, instead of a top-centre card. It fills teal, turns blue while submerged and orange with a gentle pulse when low (no pulse with reduced motion); the remaining seconds sit in the middle. It hides on dry land once full, aboard a boat and while wearing scuba gear. A visually hidden `progress` element and hint text keep the exact value and warnings available to assistive technology.

### Diving

While swimming, hold **C** (controller **B**, touch **Dive**) to descend; hold **Space** (**A**, touch **Up**) to swim up; let go and gentle buoyancy returns you to the surface. Descent is **1.3 m/s**, swimming up **1.6 m/s**, buoyancy **0.55 m/s**, all eased; submerged travel is **1.15 m/s**. Depth stops **0.3 m** above the seabed, a rising seabed pushes a diver up, and reaching shallows ends the dive. Below **0.45 m** the head is under: the underwater countdown begins (scuba below is unlimited). An exhausted swimmer cannot dive. The rig tips head-down while descending and upright while rising; it is still pose-only. Tuning lives in `AVATAR_DIVE` (`src/viewer/avatarController.ts`); `diveDepth` is part of controller state and round-trips through snapshots; older snapshots resume at the surface.

When a diver's camera target goes more than 0.6 m under, the follow camera dips beneath the surface with them and eases back up after surfacing. Under water the scene switches to a short teal fog (the shared `STYLE.dome.below` tone, 0.8–24 m), hides the sky dome and uses the water shader's existing underside shading for the surface overhead. The seabed now uses a separate [survey-backed floor](bathymetry.md), with an authored coastal join and explicit gap handling. Divers and Otter Man share its rendered Near triangles; the old sloping strip and flat five-metre floor are removed. Kelp canopy mats float just under the surface offshore. The kelp-forest [dive site](gym-dive-site.md) adds kelp, fish and seabed life from the library.

### Dive boat and scuba

The library **Marigold cabin boat** (`createCabinBoat()`, 5.52 × 2.40 m) is moored off the end of the mapped concrete pier route, stern to the pier, bobbing on the same wave function as the rowboat. While aboard, **W/S** and **A/D** drive it (Shift or controller B for faster) out to the kelp-forest [dive site](gym-dive-site.md). Its hull collision follows it for swimmers and the rowboat. Walk to the pier's end and press **E** (**X** / tap) to **Board the dive boat**; you stand on the open stern deck by a new **scuba gear rack** (`createScubaRack()`, one matte draw). On deck the prompt offers **Put on scuba gear** / **Step onto the pier**; once suited, **Dive in** / **Take off scuba gear** (secondary prompt **R**, controller **Y**). Diving in drops you off the starboard side wherever the boat is; swim back near the starboard ladder for **Climb aboard**, which works while swimming or diving. **Step onto the pier** appears only near the mooring.

Scuba is deliberately cozy: **the tank never runs out**, no air to manage or refill, and the breath ring hides. Gear only speeds diving (descend 1.7 m/s, travel 1.6 m/s). Without gear the 20-second underwater rule above still applies. **Back to start**, leaving the gym and loading a character return the gear to the locker. Saves and JSON recipes never include gear.

Gear is part of the avatar's one skinned batch: `createAvatarModel(design, { gear: 'scuba' })` swaps the outfit for a dark wetsuit, replaces the hairstyle with a hood, and adds mask, strap, regulator, tank, harness, weight belt and fins on the existing bones. **Still 1 draw, 0 textures, 17 bones**; 3,912 triangles on the default character and at most 3,994 across hair/face/size combinations. Hiding the hairstyle under the hood keeps the worst case inside the 5,000 ceiling. Tank size is shortened to suit the toy proportions. The mooring, deck positions and locker are authored placements, not records of a real dive operation.

Swimming speed is **1.35 m/s**; Shift does not accelerate a swimmer. The 17-bone rig blends between forward strokes and stationary sculling, suppresses incompatible emotes/casting/carry poses, and retains blinking. The borrowed rod returns to its station when swimming begins. Ground contact is hidden in water. Boat controls remain separate; boarding and land interactions are unavailable while swimming.

Controller state stays separate from the appearance recipe. Switching characters, changing an outfit or visiting another tab retains the current practice breath and last safe position; these do not refill it. The hidden gym pauses its simulation. A page reload starts a new practice session. Saves and portable JSON continue to store appearance only.

The water mask follows the mapped coastline and bounded offshore area; low elevation alone never identifies water, and the inland pool is not a swim area. Existing land/access heights and solid collision proxies are retained. Offshore movement uses the separate **USGS bathymetry** dataset, with documented shore joins and NoData approximations; it does not reuse offshore land-DEM values. The visible water level is the gym's static display reference, not a live tide. Animation and swimming add **no meshes, draw calls, materials, image maps or geometry uploads**; only existing bones and root placement change. Tuning lives in `AVATAR_SWIMMING` in `src/viewer/avatarController.ts`.

See the swimming review (historical authoring evidence omitted from this public snapshot) for verification and browser scope.

## Model and world budgets

| --- | --- | --- |
| Avatar color pass | **1 draw, 1 material** | 1 draw for the core avatar; equipment and scene contact are separate |
| Avatar Near geometry | Default **3,453 triangles**; maximum **4,270** over 810 appearance combinations; scuba gear **3,912** default / **3,994** maximum | 5,000 triangles maximum |
| Default Mid / Far geometry | **1,720 / 684 triangles**, still 1 draw | Shared projected-size LOD; forced close views are for inspection |

Face lines stay inside the original skinned color batch: **Soft adds 20 Near triangles**, and **Defined adds 58**. On the default character, Soft uses **3,473 / 1,730 / 688** Near/Mid/Far triangles and Defined uses **3,511 / 1,748 / 696**. Both remain one draw with no additional materials, textures or bones. Face-lines evidence (historical authoring evidence omitted from this public snapshot).

The shared generated toon ramp and GPU skinning data are distinct from per-avatar image textures. A character's appearance recipe is not its entire first visit download: Three.js, application code, the avatar factory and the local map subset are also loaded. Geometry is generated on the client rather than downloaded as a GLB. The avatar workbench and gym are lazy modules. The current application's existing main viewer still initializes its asset scenes; this work does not claim a minimal standalone game shell.

The final October 22 creator build reported **18.80 kB gzip** for the avatar workbench JavaScript and **3.41 kB gzip** for its CSS, plus **27.46 kB gzip** for the terrain-enabled gym module. That is about **49.67 kB gzip** of feature chunks after shared application dependencies. The first flat-gym version was **30.3 kB gzip**; that earlier total is historical. See the dated avatar review (historical authoring evidence omitted from this public snapshot) and gym review (historical authoring evidence omitted from this public snapshot). These are build compression estimates, not measured network transfers; the development server and a deployment without compression will transfer more.

The gym adds the avatar, procedural weather sky, optional rain and one simple geometric ground contact disk to the park budget; the reef is a separate root with its own budget and proximity gating. See [weather sources](weather-sources.md) and [dive-site costs](gym-dive-site.md#budget-and-interest-management). It uses three blended sun shadow maps (1024² each on Base / 2048² each on Standard), fitted to the camera view through walking, flight and zoom. The far cascade fades behind local clear-weather fog; coverage evidence and rendering overhead (historical authoring evidence omitted from this public snapshot). The studio also casts onto its plinth. The contact disk remains a low-light fallback. Default Balanced ocean water has no refraction capture or underwater postprocessing. The separate [Enhanced water option](graphics-quality.md) adds bounded HDR refraction, RGB transport, caustics and optional shafts on native WebGPU. The workbench uses the project's Base/Standard pixel ratio policy and the shared shader system on native WebGPU or WebGL 2 (`?webgl`). Model counters describe one color pass; submitted renderer totals include culling and backend output passes. Geometry levels do not change collision, identity, equipment attachment or animation ownership.

One draw per independently animated player is a useful foundation, not proof of large multiplayer scale. A large world will still need interest management, animation update throttling, spatial scene batches, reuse of identical geometry, and measured crowd limits on actual phones. Distance LOD lowers triangles; it does not remove bone updates or merge independent avatars into an instanced draw. No multiplayer capacity or physical-phone FPS target is claimed by this prototype.

## Geography, visual references and scale

The avatar follows the project style guide: broad head/body proportions, readable faces, friendly colors and mix-and-match controls. Model, clothing shapes, UI and palette are original procedural work.

The avatar has a selected nominal height of **1.20–1.80 m**, defaulting to **1.45 m**, with an unscaled root. Hair brings the original-size range to **1.447–1.524 m**; the measured hair-inclusive range across both height extremes is **1.198–1.892 m**. All bounds and attachment points use the chosen metre size. Height, build and proportions are artistic. The factory publishes `dimensions` and a matching coarse capsule guide; the gym uses `controllerRadius`, `swimDepth`, `swimImmersion` and `seatedContactHeight` to fit movement and seating to the character. Cameras frame the model rather than resizing it. These guides are conservative gameplay approximations, not a body-contact or garment-physics simulation.

Lovers Point uses the existing OpenStreetMap coastline, paths and building footprints, with City of Pacific Grove photographs informing the cypress, granite, coves and Beach House facade. Beach, pool and court outlines now come from the October 22 map extract; roads and footpaths are classified separately. The gym follows cached USGS terrain and authored walkable access surfaces; the [geographic sources and limits](testing-gym-geography.md) record elevation provenance and the remaining authored structures, widths, planting and exercise stations. The current [live-feed inventory](live-feeds.md) and [real-time data plan](real-time-world.md) remain separate from the gym's static environment.

## Source ownership and checks

- `src/models/avatar/design.ts`: version-independent appearance recipe, option sets and normalization.
- `src/models/avatar/sizing.ts`: shared metre dimensions, body shape transform and contact guides.
- `src/models/avatar/geometry.ts` and `index.ts`: procedural parts, shared skinning, attachment bones, animation and disposal.
- `src/data/avatarSaves.ts`: versioned local collection and portable recipe parsing.
- `src/viewer/avatarWorkbench.ts` / `.css`: creator, persistence controls, renderer lifecycle, camera, input and interactions.
- `src/viewer/avatarController.ts`: metre-scale movement and collision, independent of the renderer.
- `src/viewer/testingGym.ts`, `src/viewer/testingGym/` and the two Lovers Point JSON files: mapped world, photo-informed components, spatial instances and stations.

Run `npm test`, `npm run build`, `node tests/avatar-browser.mjs` and `node tests/avatar-swimming-browser.mjs` and `node tests/avatar-sizing-browser.mjs`. The focused model tests cover every silhouette combination, finite/normalized skinning, immutable animation buffers, timing consistency, all LODs and disposal. Controller checks cover diagonal speed, collision tunnelling, coast bounds and scene budgets. Save checks cover round trips, corrupt collections and invalid imports. The browser suite covers actual creator/save/load flows, keyboard and touch movement, equipment, emotes, scene suspension and both renderer backends. Browser evidence and the exact environments checked are recorded in the review (historical authoring evidence omitted from this public snapshot).

Sizing adds no Near vertices, draws, materials or image maps. Mid/Far simplification can vary by a few triangles with the body shape; the sampled default-look extremes use 1,720–1,722 Mid and 683–686 Far triangles, within the same budgets. The selected shape is baked into positions, normals and bind pivots at creation; subsequent animation uses the existing bones. See the sizing review (historical authoring evidence omitted from this public snapshot) for current measurements and browser evidence.

The next avatar experiment is to measure a crowd of saved characters on representative mobile hardware, reuse identical geometry, and throttle distant animation before choosing multiplayer population limits. Terrain routes and vertical placement have their own gym checks.
